# Security and data governance

What is enforced today, what is deliberately not, and where each control lives
in this repository and in `vpn-data-platform-apps`. A gap stated plainly is
more useful than a control that is claimed and missing, so section 6 lists
what is absent.

## 1. Network: nothing is public

There is no public endpoint for any part of the platform.

| Control | Where |
|---|---|
| **Tailscale** is the only way in. A subnet router (`t4g.nano`, which is also the NAT for private subnets) advertises the VPC range `10.42.0.0/16` to the tailnet | `terraform/02_tailscale_router` |
| **One internal ALB**, group `vpn-data-platform-internal`, scheme `internal`, `inbound-cidrs 10.42.0.0/16` on every Ingress | Ingress annotations in the apps repo |
| **TLS** on every hostname: an ACM wildcard certificate on that ALB; DNS records written into Cloudflare by external-dns (upsert-only, so it never deletes a record it did not create). The records resolve to private ALB addresses, so they are useless off the tailnet | `terraform/04_ingress` |
| **EKS API** has a private endpoint only; `kubectl` works over the tailnet | `terraform/03_eks` |
| **RDS** has no public endpoint; its security group admits only the cluster | `terraform/06_data_foundation` |

This replaces a source-IP allowlist: identity is the tailnet device and user,
not an address that changes when someone moves network.

## 2. Human and BI access to data — Trino

Everything a person reads arrives through Trino, over HTTPS, with a password.

| Control | Where |
|---|---|
| **Password authentication** — bcrypt password file, passwords generated by the bootstrap script and kept in Secrets Manager (`trino-user-*`) | `bootstrap/trino.sh`, `apps/trino` |
| **File-based access control** — rules mounted from a ConfigMap | `apps/trino` values → `accessControl` |
| **Resource groups** — limit concurrent and queued queries per user group | same values file |

| Account | Can read | Can write | Use |
|---|---|---|---|
| `etl_setup` | everything | everything | operator, terminal use only |
| `team_b_powerbi` | `gold` (and its sub-namespaces), `system.jdbc`, `information_schema` | nothing | the credential a BI tool holds |
| `non_powerbi` | same as above | nothing | ad-hoc analysts |

Gold is the only layer with a contract. Bronze is a verbatim copy of what the
source sent and silver's shape changes with every cleaning rule, so limiting
readers to gold protects their dashboards as much as it protects the data.

**What this does not do:** access is per schema. There is no column masking
and no row filtering — a gold reader reads every column and row of a gold
table. Trino supports both in the same rules file; neither is configured.

## 3. Workload access to AWS — Pod Identity

No pod holds a static AWS key, with one exception. Six IAM roles are bound to
ServiceAccounts through EKS Pod Identity:

| Role | Used by | Can do |
|---|---|---|
| AWS Load Balancer Controller | `kube-system` | manage the internal ALB and target groups |
| EBS CSI driver | `kube-system` | create and attach volumes for PersistentVolumeClaims |
| Polaris service → **Polaris storage role** | `polaris` | Polaris assumes the storage role, which is the only role with read and write on the warehouse bucket (`bronze/*`, `silver/*`, `gold/*`) |
| Karpenter | `karpenter` | launch and terminate nodes inside its NodePools |
| Spark | `spark/spark` | write `logs/spark-events/*` only — no warehouse access of its own |
| Airflow | five Airflow ServiceAccounts | read and write `logs/airflow/*` only |

**The exception — Harbor.** Harbor's registry storage driver does not use the
Pod Identity credential chain, so it authenticates to S3 with an IAM user
access key (`vpn-data-platform-harbor-registry`). The key is scoped to the
registry bucket only and stored in Secrets Manager (`harbor-s3`). Rotation is
in `BACKLOG.md`.

## 4. Catalog-level access — Polaris

Spark does not touch table data with its own AWS role. It authenticates to
Polaris as principal **`etl`**, and Polaris vends short-lived S3 credentials
scoped to that table (`X-Iceberg-Access-Delegation: vended-credentials`). The
`etl` principal holds content-management privileges on the `data_platform`
catalog, created idempotently by `bootstrap/spark.sh`.

This is the control that actually binds: a compromised Spark pod can reach what
`etl` may write, not the whole bucket. When Spark cannot write a table, the
policy to read is the **storage role's**, not Spark's.

**Gap:** Trino still connects to Polaris with the **root** credential. A
dedicated read-mostly principal for Trino is in `BACKLOG.md`.

The Polaris management API (create catalogs, principals, grants) has no
Ingress; it is reached only with `kubectl port-forward`.

## 5. Secrets

About nineteen credentials, generated by `openssl rand` (or by AWS for the RDS
master password) inside `bootstrap/*.sh`, stored in AWS Secrets Manager, and
written into the cluster with `kubectl create secret … --dry-run=client -o yaml
| kubectl apply -f -`. None is passed as a command-line argument and none is in
either repository.

| Group | Secrets |
|---|---|
| network | `tailscale-auth-key` |
| catalog | `polaris-db`, `polaris-root`, `polaris-etl` |
| query engine | `trino-user-etl_setup`, `trino-user-team_b_powerbi`, `trino-user-non_powerbi`, `trino-internal-shared-secret` |
| monitoring | `grafana-admin-password` |
| registry | `harbor-db`, `harbor-s3`, `harbor-internal`, `harbor-robot-spark-pull`, `harbor-robot-ci-push` |
| orchestration | `airflow-db`, `airflow-internal`, `airflow-admin` |
| CI | `github-runner-token` |
| database | RDS-managed master secret |

One credential is outside Secrets Manager on purpose: the **Cloudflare API
token** for external-dns and certificate validation is a Kubernetes Secret
created by hand before `terraform/04_ingress` runs, so it never enters
Terraform state.

**Pinned, not generated by charts.** Harbor's and Airflow's charts generate
keys and certificates at render time. Under Argo CD every render is new, so
those values would rotate on every sync and break sessions and encrypted data.
Each is created once by the bootstrap script and referenced as an existing
Secret.

What a Kubernetes Secret still is: base64 in etcd, readable by anything with
`get secrets` in that namespace. EKS envelope encryption with a KMS key is not
enabled.

## 6. Gaps, stated plainly

| Gap | Consequence today | What closing it takes |
|---|---|---|
| **No NetworkPolicy** | any pod can reach any Service in the cluster | default-deny per namespace plus explicit allows, tested against every real path |
| **No query audit log** | nothing records who ran which query | Trino event listener writing to the logs bucket (a `trino-audit/` prefix with 365-day retention, see [DATA_TIER.md](DATA_TIER.md)) |
| **No column masking or row filtering** | gold readers see every column and row | same Trino rules file |
| **No SSO** | static password file; adding a person means re-running the bootstrap | OIDC against an identity provider |
| **No customer-managed KMS keys** | S3 uses SSE-S3, RDS the AWS-managed key | SSE-KMS with a customer key |
| **Argo CD `default` AppProject** | any Application can deploy anywhere | scoped AppProjects per area |
| **No Tailscale ACLs** | every tailnet device reaches every hostname | tailnet policy by user or tag |
| **Prometheus has no login** | anyone on the tailnet can read metrics | `enableAdminAPI: false` keeps it read-only; an auth proxy in front |
| **Trino uses Polaris root** | see section 4 | dedicated principal |
| **One EKS admin** | losing that identity loses the cluster | a second access entry |
| **Local Terraform state** | state lives on one laptop | S3 backend with locking |
| **EKS control-plane logs off** | no Kubernetes API audit trail | enable the `audit` log type when someone will read it — it costs CloudWatch ingestion |

## 7. Governance

### Business data

Iceberg tables are governed by the layout, categories and lifecycle in
[DATA_TIER.md](DATA_TIER.md). The classification is the namespace path itself —
`medallion.category.domain` — so `bronze.financial.*` and `bronze.log.*` get
different retention without a separate mapping to maintain.

### Platform data

| Data | Where | Policy |
|---|---|---|
| Polaris catalog metadata | RDS PostgreSQL | critical state — losing it loses every table pointer. RDS automated backups, no expiry |
| Harbor and Airflow metadata | same RDS instance, own databases | automated backups |
| Airflow task logs | S3 `logs/airflow/` | 30 days |
| Spark event logs | S3 `logs/spark-events/` | 30 days |
| Prometheus metrics | EBS, 7 days | local retention only |
| Container images | S3 registry bucket via Harbor | Harbor retention and garbage collection |

### Lineage

Every bronze row carries three columns:

| Column | Meaning |
|---|---|
| `_ingested_at` | when the row was loaded |
| `_source_file` | the exact source object it came from |
| `_run_id` | the Spark job that loaded it (the SparkApplication name, which contains the processing date) |

Silver and gold are rebuilt from bronze by partition (`trip_date` in the
sample pipeline), so a gold row traces back through silver to a source file
and the job that loaded it.
