# Backlog

Known gaps in what is built so far, with the reason each matters and when it
stops being optional. Written 12 October 2026, after stages 01–05.

## Before something specific happens

| When | Item | Why |
|---|---|---|
| ~~Before the next component~~ **Done in stage 03** | ~~Pod limit on the single t3.medium (17 pods)~~ | Fixed with VPC CNI prefix delegation and replacement node groups: the limit is now 110 per node. What limits the node from here is CPU and memory (2 vCPU, 4 GiB) — Polaris, Trino and Airflow will need more nodes or a larger type when they arrive. |
| **Before the Tailscale auth key expires** (≤90 days from creation) | Rotate the key in Secrets Manager | The running router is unaffected — it already joined. But any rebuild of the router (a changed boot script, a destroy/apply) needs a valid key to join again. Generate a new reusable key and `aws secretsmanager put-secret-value --secret-id vpn-data-platform/tailscale-auth-key --secret-string ...`. |
| **Before inviting anyone else to the tailnet** | Tailscale ACLs | The default policy lets every tailnet member reach everything, including the whole VPC through the subnet route. Restrict it (for example: members reach only the ALB's port 443; admins reach the Kubernetes API). |
| **Before installing anything important** | A second EKS admin | Only the IAM identity that ran `terraform apply` in stage 03 is cluster admin. If that identity changes or is lost, nobody can use kubectl. Add an access entry for a second principal. |
| **Before a second person runs Terraform** | Move state to S3 with `use_lockfile = true` | State is on one laptop. Lose it and Terraform forgets what it built; two people with two copies will fight. Stages 02–05 read stage 01's state from `../01_vpc/terraform.tfstate`, so they move together. |
| **Before moving each old service** | Delete its old Cloudflare record | `trino`, `airflow`, `harbor`, `grafana`, `prometheus` still point at the old platform's deleted ALB. external-dns will not overwrite a record it does not own. Keep `ssh.nopega.net`. |

## Whenever there is time

| Item | Why |
|---|---|
| ALB idle timeout for Trino | A wide scan's first response can exceed the ALB's 60 s idle timeout. `alb.ingress.kubernetes.io/load-balancer-attributes: idle_timeout.timeout_seconds=600` fixes it, but must be set on **every** Ingress in the `vpn-data-platform-internal` group at once (Argo CD in terraform/05, smoke-test, Trino) -- a mismatch makes the controller reject the newest Ingress. |
| Dedicated Polaris principal for Trino | Trino uses the Polaris root credential, as the original did. A principal with only the catalog roles Trino needs would limit the damage if that credential leaked. |
| Catalog creation as an Argo CD PostSync Job | `bootstrap/polaris_catalog.sh` is run by hand from the Mac after Polaris is up. A PostSync hook Job in the Polaris Application would create the catalog in-cluster, automatically, on every rebuild. (`bootstrap/polaris.sh` stays manual on purpose: it needs the RDS master login, which should not live in the cluster.) |
| ~~Cluster autoscaler or Karpenter~~ **Karpenter, stage 07** | Done once stage 07 is applied and the NodePools are enabled in the apps repo. Follow-up: remove the managed `ng-spot` group from stage 03 -- `spot-batch` replaces it. |
| EBS volumes are pinned to one zone | The on-demand node can land in 1a or 1b. A PersistentVolume created in one zone cannot follow a pod to the other; after a node replacement into the other zone, that pod stays `Pending`. Same failure the original platform hit with Prometheus. Options: a node group per zone, or `volumeBindingMode: WaitForFirstConsumer` plus keeping a node in each zone. |
| Router recovers itself | If the instance fails, nothing replaces it: users lose the way in, nodes lose the way out. An Auto Scaling group of one, or an EC2 recover alarm, would bring it back without a human. |
| Router OS updates | It accepts UDP from the internet (Tailscale's port) and nothing patches it. `dnf upgrade` on a schedule, or rebuild it from the latest AMI periodically. |
| Old ACM validation records in Cloudflare | Seven `_….nopega.net` CNAMEs for the old per-name certificates. Harmless, just clutter. **Do not delete `_d23aca41….nopega.net`** — it belongs to the current wildcard certificate and ACM re-reads it to renew. |
| `problem2_answer/docs/COST.md` | Quotes the NAT gateway at $32/mo — the us-east-1 rate. Singapore is $0.059/hr, about $43/mo. |
| `problem2_answer` Kubernetes version | The original runs 1.34, whose standard support ends **2 December 2026**. Rebuilding it unchanged after that date bills the control plane at the extended rate, six times higher. |
| Argo CD: fixing a child Application whose sync is stuck | Lesson from monitoring. A child's spec (`apps/*.yaml`) is applied by `root`, and `root` waits for that child's wave to become healthy -- so a pushed fix never reaches a stuck child. Setting `status.operationState.phase=Terminating` was not enough. What worked: clear `operation` and `status.operationState` (merge patch with `null`), request a sync through `operation`, then `kubectl -n argocd rollout restart statefulset argocd-application-controller`. Also check every new chart for Helm hook Jobs with `ttlSecondsAfterFinished`: Kubernetes deletes the Job before Argo CD records it finished, and the sync waits forever. |
| Rotate Harbor's S3 access key | `bootstrap/harbor.sh` creates one long-lived key for `vpn-data-platform-harbor-registry`. To rotate: create a second key, put it in `vpn-data-platform/harbor-s3`, re-run the script, restart the registry pod, delete the old key. Goes away when Harbor ships distribution 3 (AWS SDK v2, Pod Identity works). |
| Spark history server | Event logs already land in `s3://<logs>/spark-events/` (stage 09). The original ran a history server reading them, so a finished job's stages and executors stay viewable after the driver is gone. Add it as a Deployment + Ingress (`spark-history.nopega.net`) in `workloads/spark`, running as ServiceAccount `spark` (read access is already in its policy). |
| Bring over the NYC taxi pipeline | `nyc_taxi_medallion` and its three SparkApplication templates were written for the old platform (buckets, `polaris.data-platform.svc`, IRSA provider, namespaces made by old scripts). Port them into the apps repo's `dags/` following `dags/spark/smoke_test.yaml`. Details in `dags/README.md`. |
| Airflow email alerts | The original sent failure mail through an SMTP connection from Secret `airflow-smtp`. Turned off here (`secret: []` in `apps/airflow.yaml`) because the Secret does not exist and its absence stops every Airflow pod. Recreate it from Secrets Manager in `bootstrap/airflow.sh`, then restore the `secret:` entry. |
| RDS connection budget | db.t4g.micro allows about 110 connections, shared by Polaris, Harbor (capped at 30 in `apps/harbor.yaml`) and Airflow (each component and every task pod opens its own pool). Watch `DatabaseConnections` in CloudWatch once pipelines run; the fix is PgBouncer (`pgbouncer.enabled` in the Airflow chart) or db.t4g.small. |
| Split DNS for the EKS endpoint | The Tailscale split-DNS rule for `ap-southeast-1.eks.amazonaws.com` may not be needed if the private endpoint name resolves publicly. Confirm with `dig @1.1.1.1 <endpoint host>`; if it returns 10.42.x.x, remove the rule and the README section in stage 03. |
| Spark image: single AWS SDK | The datapipeline image ships `bundle-2.24.6.jar` (for hadoop-aws) next to `iceberg-aws-bundle-1.11.0.jar`, which carries a newer AWS SDK v2. The old copy wins on the classpath, so Iceberg's `VendedCredentialsProvider.close()` hits `NoSuchMethodError: IoUtils.closeQuietlyV2` and kills the executor (exit code 50) whenever Spark frees a broadcast table mid-job. Worked around in `dags/earthquakes/templates/*.yaml` with `spark.cleaner.referenceTracking: "false"`. Fix: set `AWS_SDK_VERSION` in `images/spark/Dockerfile` to the SDK version inside iceberg-aws-bundle 1.11.0, confirm hadoop-aws 3.4.1 still works (Spark event logs to `s3a://`), release `spark-v0.2.1`, then drop the workaround. |
